## Why CUDA 12.4 is the engineering candidate

The laptop driver reports a CUDA compatibility level newer than the candidate CUDA 12.4 runtime family. MAVI already carries test and provenance fixtures for the `2.6.0+cu124` graph, and retaining that graph minimizes unnecessary simultaneous changes.

This is a **candidate selection rationale**, not qualification evidence.

The following still must be proven before the candidate can be called engineering-qualified:

- exact Windows wheels are obtainable and hash-frozen;
- the full third-party dependency closure is reproducible;
- MMCV native/CUDA operations are compatible with the selected Torch/CUDA ABI;
- a clean offline venv installs with strict no-index/hash-only semantics;
- `torch.cuda.is_available()` is true on the observed machine;
- `cuda:0` maps to the expected NVIDIA GPU;
- real RTMDet inference completes on CUDA;
- no CPU fallback occurs under explicit CUDA;
- the Runtime Pack can be reproduced with a stable content identity.

## Native ABI rule

C1 does **not** freeze the final MSVC/Windows SDK native ABI string.

C2 must capture the actual toolchain identity used to build or validate native CUDA/MMCV artifacts. The final ABI identity is frozen only with the reproducible CUDA lock/Runtime Pack inputs.

This prevents the repository from inventing a compiler/SDK identity before the native build path is observed.

## 4 GB VRAM operating constraint

The development GPU has 4096 MiB VRAM.

Until measured otherwise:

- use one inference worker;
- use batch size 1;
- avoid concurrent CUDA inference jobs;
- capture peak/steady GPU-memory use during C4/C6;
- treat any performance measurements as engineering characterization only;
- do not derive Production thresholds from this laptop.

The memory constraint must not be worked around by silent CPU fallback or by changing the model without a separate design decision.

## C1 change-control rule

Any change to the following requires an explicit C1 revision before C2 continues:

- CPython major/minor/patch;
- PyTorch semantic version or CUDA build;
- torchvision semantic version or CUDA build;
- MMCV/MMEngine/MMDetection semantic versions;
- target CUDA runtime family;
- native build strategy that changes the ABI boundary.

A failed C2/C4 experiment may justify a new candidate, but the failed candidate and reason must be documented rather than silently replaced.

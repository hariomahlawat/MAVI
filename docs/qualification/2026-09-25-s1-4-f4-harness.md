## 2. Checker rules added (each with a negative test and a recorded mutant)

- **B3-A:** `max ≤ min(15 s, timeout/2)` on each variant (`hand_off_bound_violated`). The output must be authoritative at the worst shape with the finalizer off, and every sample must hold its invariants (`b3a_output_mismatch`).
- **B3-B:** `max ≤ ½ frozen MaximumFinalizationDurationSeconds` (`finalization_bound_violated`). The output must show:
  - the hosted service, with options from `appsettings.json` and activated;
  - the configuration equal to `appsettings.json` at the measured SHA (`frozen_configuration_mismatch`);
  - the barrier SQL read from the measured source (`barrier_hold_unbound`);
  - the extension count equal to `⌈50000/SealingBatchSize⌉ + 1`;
  - one publication, exactly one sequence allocation inside its PublishAsync, and no premature visibility;
  - per-sample API contention with zero errors, and per-sample RSS and CPU;
  - the §9.2 concurrency block (`concurrency_integrity_failed`): two jobs, both published once with one allocation each, live claims ≤ the committed limit, and with a limit of one the second job unclaimed until the first published;
  - the command timeout equal to the shipped runtime's at the measured SHA (Npgsql's 30 s default unless the committed connection string sets one), and the longest command within it;
  - no rejected timeline, and every bracket proof true (`publication_timeline_invalid`);
  - a positive graph persistence (`graph_persistence_unbound`);
  - at least five reference samples.
- **Shipped activation:** B3 passes only where the measured SHA ships the path it qualifies: `VisionFinalization:Enabled = true` in `appsettings.json` and the worker `completion_schema_version` default `"3.1"` (F4 plan §10.5, closure criterion 2) (`activation_default_unqualified`). On `main` today both are off, so B3 cannot pass before F4-C, however the harness ran.
- **Recomputation:** every B3 timing equals the statistics recomputed from its producer's raw samples or ticks. Barrier hold, wait, publication transaction and graph persistence each come from two timestamps. A typed or subtraction-derived value is `metric_without_producer`.
- **Ordering invariant:** `rowLockAcquired < graphPersistenceStart ≤ graphPersistenceEnd < barrierCommandStarted ≤ barrierAcquired < commitCompleted`, and `commitStarted < commitCompleted`.
- **B3-A release proof:** every sample shows `workerReleased` (`b3a_output_mismatch`).
- **Crash matrix:** the four H rows, each converged to one publication, with the run's Track rows equal to one graph, a stable sequence, at most one live claim, and created + adopted equal to the expected objects. Mid-seal must adopt, and the worker row must have killed a live worker (`crash_matrix_incomplete`).
- **B4 variants:** B4's Python suites are required on both variants (§14); its .NET suites once.
- **Provenance:** each B3 output comes from its own local run, stamped with the harness run id (`artifact_run_mismatch`). It carries its own variant and differs byte-wise from the other variant's output. Every artifact of a PASS lies under `evidence/<measured-sha12>/`, compared as a normalized relative path so `..` segments cannot escape it (`artifact_not_from_measured_sha`). This refuses PR #87's `bb331c6` files.
- **Storage:** host `storageClass` needs `storageClassEvidence` (schema). The storage class is bound for B2 and B3, and a hosted runner is refused for B3 timing (`storage_class_unbound`).
- **Disconnected v2:** the run must be activated (`Enabled=true`, 3.1). The dependency diff must add nothing, the connect trace must show loopback only, and the runtime manifests must be hash-bound (`disconnected_run_incomplete`).

## 3. Plan corrections found while implementing

- **Command timeout.** The plan's `CommandTimeoutSeconds 300` is `DatabaseMigrations:CommandTimeoutSeconds`, which applies to migrations only. The runtime `DbContext` uses the connection string's or Npgsql's default (30 s). The B3-B harness measures the effective value. The checker requires it to equal the shipped runtime's at the measured SHA, so a test connection string cannot loosen it. This is stricter than the plan text.
- **Graph-persistence end.** The plan names the barrier command's start as the end of graph persistence while requiring `graphPersistenceEnd < barrierCommandStarted`. The harness ends graph persistence at AddAsync's own `SavedChanges`, its last observable event. The bracket proof shows nothing happens between that and the barrier command.
- **Visibility sequence count.** Track search and analytics snapshots also call `nextval` on `processing_visibility_sequence`. "One sequence" is therefore the job's run having exactly one assigned `visibility_sequence`, never the global counter.
- **B4 staging-survival proof.** `test_current_attempt_staging_survives_the_hand_off` lives in `test_worker_runner.py`, which no workflow retained. Task 10's boundary step now runs `test_worker_client.py` and `test_worker_runner.py`, so the B4 proof has a retained result.
- **Worker row shape.** The real-worker H row uses `tools/vision/dev/fixture_worker_harness.py` (the real `WorkerRunner` and client, 3.1, fixture detector and tracker). No repository tool produces a 10,000-Track real-worker completion without the model runtime, so that row runs at the fixture's natural shape and records it. Envelope-size worker independence is B3-B's, which never runs a worker.

## 4. Running the harnesses (operator, at M2 only)

```
export MAVI_TEST_DB_CONNECTION="Host=...;Database=mavi_test;..."   # PostgreSQL 18
export MAVI_QUALIFICATION=1 MAVI_QUALIFICATION_OUT=<out>
MAVI_S1_HANDOFF_ROOT=<qualified fs> dotnet test tests/Mavi.IntegrationTests --filter "FullyQualifiedName~S1HandOffScaleTests"
MAVI_S1_ENVELOPE_ROOT=<qualified fs> dotnet test tests/Mavi.IntegrationTests --filter "FullyQualifiedName~S1FinalizationEnvelopeTests"
MAVI_S1_RECOVERY_ROOT=<qualified fs> MAVI_S1_WORKER_PYTHON=<worker venv python> dotnet test tests/Mavi.IntegrationTests --filter "FullyQualifiedName~S1FinalizationRecoveryTests"
```

Budgets on the development container class:
- B3-A: roughly 1–2 h per OS, dominated by staging 50,000 objects per sample.
- B3-B: roughly 1.5–2 h plus about 15 min of reference.
- Crash matrix: roughly 1 h. The mid-seal row waits one `ClaimSeconds` for the dead claim to expire.

On Windows, set `MAVI_QUALIFICATION_WINDOWS_DISK_EVIDENCE` and `MAVI_QUALIFICATION_WINDOWS_DISK_ID` so the storage class is measured, not unknown.

## 5. Residual trust

The checker verifies that retained bytes match their hashes and their content, and it recomputes every B3 interval from retained raw ticks. It cannot verify offline that ticks were produced by the harness rather than written by hand. The harness run id, the git SHA, the clean-tree flag and the host binding raise the cost of that, but do not eliminate it. The F4 closure's independent review of the executed record remains part of the gate.
